# 产品需求与用户决定

## 1. 目标与当前范围

做一个帮助成年人“提问 → 理解 → 自动整理 → 主动复习 → 查漏补缺”的学习 App。产品暂名知回 / Knowledge Review；名字由开发阶段暂定，未经过用户正式命名确认。

最终面向其他用户，支持 Android、iPhone、Windows、macOS、网页。手机和电脑上的同一账号同步问答、知识点、复习进度与设置。中英双语界面，学习语言与界面语言分别考虑。

最终发布中国大陆及海外。用户之后明确：目前先不考虑发布，逐步实现功能，预留发布设置，避免返工。不要现在执行上架、购买服务或假定所有地区可共用一套服务。

## 2. 提问与模型

- 文字提问和语音转文字提问；没有要求语音朗读答案。
- 用户填写自己的模型 API Key，模型商费用由用户在外部承担；App 内操作免费，不在 App 内处理外部模型付款。
- 用户没有指定模型商，需可扩展并按服务能力接入，不能把“用户自带 Key”理解为模型必定免费。
- 期望 Key 填一次可跨设备使用，应采用加密保存/取回，不能明文同步。
- 回答结构：直接回答 → 分步骤解释 → 生活例子 → 简短总结。
- 支持“再简单一点”“换个生活例子”等连续追问。
- 不确定时明确说“不确定”，不能强行编答案。
- 需要联网；默认不列出来源，用户询问时提供。实现可以折叠展示真实返回的来源，但必须保留关联，不事后编造链接。
- 按用户基础解释。初始各模块可选“入门、了解一些、较熟悉”；之后按表现独立调整，用户可手改。
- 调用失败、额度不足、限流、网络异常等需明确提示并保留问题；失败请求不能混入正常上下文。

## 3. 模块与知识整理

- 新用户首次使用选择所需领域。预设四模块：编程、英语、工作知识、生活常识。
- 模块的聊天记录、水平、知识点和复习进度相互独立；首页汇总今日复习。
- 分类自动完成，但允许用户纠正。分类应能识别问题所属模块及更细主题。
- “待办”指待复习知识点，不是普通事务任务清单。
- 默认自动加入知识点；支持删除、合并、暂停复习。
- 识别同义提问而非只比字面。反复提问标为重点；复习答错、仍不理解也标重点，最好分别显示原因。
- 每次原始问答按日期保留，卡片可以追溯原文；重复或合并不能丢失历史。
- 模块关闭保留历史、暂停该模块学习任务，重新启用逐步恢复是当前实现方向。此前详细恢复策略主要由助手建议，尚未单独取得用户逐条确认；不要删除旧数据。

## 4. 每日复习

- 第二天打开先提供昨天内容生成的小问题，一道一道来。也需要复习更早到期和薄弱内容。
- 支持跳过复习，随时自由提问。
- 答题形式：选择题和文字回答；没有要求语音答题。
- 依据含义判断理解，不能要求复述标准措辞。
- 未答对或仍不理解：继续讲解、重点标注、加入当天待复习知识，并继续跨天安排。
- 需要“我猜对了”“还是不懂”“已经掌握”等反馈，不能把猜对等同掌握。
- 提供每日 5/10/20 分钟计划；是建议时长，不是到点强制终止，允许继续或调整。
- 多日未打开按计划分批补，不一下塞入全部积压。
- 遵循间隔复习与遗忘规律，可借鉴背词软件体验，但用户没有指定具体算法。当前启发式排程不能包装成经实证校准的 FSRS 或记忆效果保证。
- 每周日系统只安排复习，不引入新的学习内容；用户仍可自由提问。回顾本周知识并纳入历史薄弱点。
- “周日是否纳入当天用户主动学习的内容”“跨时区旅行与夏令时”等细则可合理实现并写测试；不要反复停下来询问。

## 5. 提醒与数据

- 打开时复习弹窗；支持关闭 App 后的系统提醒。提醒须向用户说明、主动授权，可拒绝，拒绝不影响学习。
- 可自选提醒时间，按用户当地时区计算“第二天”和“周日”。
- 保存文字问答、知识及复习记录；原始录音不长期保存。
- 数据导出、删除记录、账号注销；数据隔离、备份与失败恢复为上线预留。
- 同账号多端一致，账号绑定不同登录方式后应避免形成重复账号。

## 6. 用户、登录与年龄

- 面向其他用户，不是只给本人用。
- 最终支持邮箱、手机号、Apple、Google 登录，账号绑定与合并能力需考虑。
- 仅允许 >=18 岁用户。注册提供生日判断，未成年不可完成注册或登录使用。
- 只保存成年状态及必要验证记录，不长期保存完整生日。
- 自报生日不等于真实身份验证。当前前端判断不能充当服务端年龄准入机制。

### 6.1 2026-11-01 用户新决定（覆盖上文冲突处）

- **必须登录才能使用 App。** 打开后先显示登录/注册；后端使用 Supabase。
- **注册信息**：用户名、邮箱、手机号、国家或地区、生日。用其中的邮箱或手机号接收验证码，另一项可选。
- **生日在注册时必填**，由服务端判断是否年满 18 岁（保持“仅限成年”）。原首页的“成年确认”改名为“生日”，并移到注册页。
- **学习模块、复习计划**移到注册之后，作为可跳过的一步；跳过时使用默认值（全部模块、入门、每天 10 分钟），之后可在“学习设置”修改。
- **管理员账号**可随时查看用户表：用户名、国家或地区、部分隐藏的邮箱和手机号、注册与最近登录时间、成年确认状态。管理员只能由运营者在数据库中指定。注册页向用户说明管理员可见的范围。

## 7. UI 与最新具体要求

- 简约、功能优先，手机与电脑可用，中英文一致。
- 模型设置页右上角有“配置说明”超链接。
- 用户首次打开模型设置页时弹窗说明入口位置；关闭后不重复打扰。
- 配置说明包含实际操作步骤、官方 Key 获取链接和常见问题；打开说明不丢失表单内容。
- 这一最新要求已经实现并完成浏览器验收，文件为 `model-help.js`。

## 8. 费用与协作约束

- 对后台存储、短信、同步等运营费用，用户选择“先看成本估算，再决定第一版范围”，没有授权购买服务，也没有承诺固定月预算。
- 曾讨论的“50 人 / US$200 月预算”等是建议，不是用户确认的预算。
- 早期要求每一步结束确认；后续用户明确改为“不需要询问我了，继续”。继续完成可做工作，避免重复确认。
- 本次最新任务是把全部工作整理交给 Claude；交接时保留真实状态，不替用户向外部服务发送资料。
