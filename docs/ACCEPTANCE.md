# 启动与验收清单

## 1. 本地检查

```sh
node --version
npm run check
npm test
npm start
```

当前无第三方依赖。HTTP 测试会临时监听 loopback 随机端口；受限执行环境应放行本机访问，不能将权限失败误当产品失败。不要为跑测试关闭系统安全保护。

正式预览默认 4174。若原机器已在 4180 使用，优先保留其地址，注意 localStorage 不随端口迁移。

## 2. 隔离流程验收（不需要真实 Key）

```sh
node tests/browser-fixture.mjs
```

默认地址 `http://127.0.0.1:4175/`。可用 `QA_PORT` 改端口。页面外观与产品相同，但返回内容明确包含“测试”“非真实模型输出”，没有外部调用。它不属于正常 `npm start`。

1. 打开后先出现登录页。点“注册”，填写测试用户名、`learner@example.test`、国家或地区和**测试生日**；验证码固定为 `123456`（假账号服务，不发送邮件或短信）。之后的模块和时长页可以跳过。管理员：登录页点“管理员使用密码登录”，输入 `tests/qa-admin.local.json`（本机文件，已被 git 忽略）中的用户名和密码，之后可在“管理”查看用户表。没有该文件时测试服务不创建管理员。用未注册的邮箱登录时，页面应提示“还没有注册”，并提供“去注册”按钮。用 18 岁以下的生日注册应显示“无法完成注册”。不要把测试生日当用户个人信息。
2. 模型设置首次出现位置提醒，知道了后不应重复；右上角“配置说明”打开中英帮助，返回时不丢未保存字段。
3. 隔离服务可填写 `test-only-not-real`，勾选说明并保存。**该占位符只能用于隔离服务，不能作为真实模型 Key。**
4. 完成编程提问，看到测试回答和知识卡片。继续追问观察上下文；切英语模块不混入编程内容。
5. 在 fixture 中 `TEST_ERROR` 测试错误；`TEST_WAIT` 测试停止等待。不要把请求失败记作用户知识答错。
6. 在知识库查看日期/原问答、重点原因，测试分类编辑、暂停、回收站恢复和合并。
7. 当天新卡默认未到期，点击复习里的“自主加练”进入；这不代表正常次日排程失效。
8. 文字回答中包含 `wrong` 时 fixture 判错，否则判对；“还是不懂”返回测试解释。选择题正确选项为“正确概念”，验证“猜对了”反馈。均不是智能判题质量证据。
9. 刷新检查记录保留、Key 清除；关闭模块/暂停/软删除应排除复习队列。
10. 设备页检查弹窗开关、时刻与导出入口；不要在无人许可时自动接受麦克风或通知权限。
11. 正常 `npm start` 未设置 `SUPABASE_URL` 时应显示“服务尚未配置”，不能进入 App；真实 OAuth、邮件短信送达及 RLS 另行联调。

## 3. 必须使用真实配置才能验收

- 真实模型问答结构、中文英文解释准确性、例子质量、未知内容是否明确不确定。
- 真正搜索来源与答案一致，用户追问来源可查；无来源时不伪称完成核查。
- 不同表述知识去重是否过度合并、提炼失败是否可恢复。
- 真实文本判题的同义表达、半懂、猜对和模型误判纠正。
- Supabase 四种登录、会话过期、账号隔离、RLS、并发版本冲突、Key 取回、账号注销。
- 浏览器/设备麦克风识别、权限拒绝、断网、中文英文识别与转写后编辑。
- 系统通知授权/拒绝/关闭；当前关闭页面后不支持定时推送，应确认 UI 如实提示。
- 原生构建和真机安装尚无，不能列为通过。

## 4. 工程验收

维持现有自动测试，通过后再补真正覆盖新增风险的测试。检查原始 HTML/危险 URL 不执行、上游错误不泄密、Key 不在导出/存储/日志。增加账户命名空间和导入迁移前先测试数据恢复，避免把已有用户记录重置。
