## 3. 建议马上处理的 P0/P1

第 1–7 项已于 2026-11-01（Claude 接手后）修复，见下方“已处理”。其余为交接时静态审阅的风险/待核查项，不要误称已经修复。

**已处理（2026-11-01）**

1. **本地数据账号归属**（`local-space.js`）：本机学习数据最多关联一个云账号（`knowledge-review.local-owner.v1`，记录项目 URL、用户 ID、脱敏标签）。属于其他账号的本机记录拒绝上传；未关联且有记录时须勾选“本机记录属于当前账号”才能上传，上传成功后关联。下载恢复前把被替换的本机记录连同原归属存为本机备份（最多 3 份，超出时丢弃最旧的一份，界面已说明）；备份写入失败则不做任何替换，写数据失败则全部回滚。“撤销上次恢复”交换备份与当前数据，可再次撤销。注销云账号时解除关联，本机记录保留。旧版单份备份可继续读取和撤销。
   - 限制：这是“上传/恢复归属保护”，不是同一浏览器多人分别登录的本地命名空间；未登录时任何能打开该浏览器的人都能看到本机记录。真实 Supabase 未联调。
2. **恢复后即时载入**：恢复和撤销后，资料、聊天、知识库、复习记录重新从存储读取，不需刷新，登录会话与本页 Key 保留。
3. **取回 Key 严格校验**：`acceptModelKey` 返回布尔值，无效时明确提示“未取回”。备份内无效 Key 不再阻止学习数据恢复，单独提示；口令错误、备份校验失败改为中英文提示，不显示浏览器原始错误。
   - 验证：`tests/local-space.test.js` 5 项；隔离 fixture 内以浏览器端模拟 Supabase 响应（非真实云服务）走通：未关联拒传、错误口令、无效 Key、跨账号恢复即时载入与语言切换、撤销与再撤销、另一账号上传被拒且未发出云请求。

4. **本地数据校验**：三个存储的加载器按 App 自身写入上限校验字段类型与长度。
   - 问答：问题 ≤8,000 字、回答 ≤60,000 字，并校验搜索状态、模型名等可选字段。
   - 知识卡片：标题/解释/分类/例子 120/2,400/60/1,200 字，重点原因限定取值，并校验日期、合并目标、原问答长度。
   - 复习记录：作答 ≤4,000 字、讲解 ≤6,000 字，`correct` 必须为布尔值。
   - 数量上限：对话、卡片、事件均设上限。
   - 来源链接：不安全或超长的来源被过滤，标题截断到 300 字，不阻止载入。
   - 整份数据：新增 `validateSnapshot` 统一校验，云上传前与云恢复前都使用同一校验，失败时说明是哪一部分，总量超过约 500 万字符直接拒绝。将来的 JSON 导入应复用它。
   - 卡片编辑：保存前同样校验，不会写出下次无法载入的数据。
   - 验证：`tests/schema.test.js` 3 项（App 最大长度数据可载入、畸形或超长数据被拒、整份校验与大小上限）；隔离 fixture 内经 UI 产生问答、卡片和复习记录，刷新后全部通过新校验，超长编辑被拒。
   - 限制：不符合新规则的旧数据会像以前一样显示“无法读取，未覆盖原数据”，不会被删除。服务端仍不能信任浏览器存储或自报成年，需在接入真实后端时实现。

5. **重绘与输入草稿**：逐一审查了会触发全页重绘的路径（语音结束、知识提炼、云回调、语言切换、页面内操作）。原先会丢内容的地方已修复：
   - 全页重绘：保留输入框焦点、光标或选区和滚动位置（`app.js` 的 `render`）。
   - 知识卡片编辑表单：未保存的修改、模块选择、合并目标、展开状态在重绘和语言切换后保留；显示“有未保存的修改”，可“放弃修改”。数据被云恢复替换时清空草稿。
   - 问答草稿：切换或新建对话不再清空。“再简单一点”“换个例子”“放回输入框”改为追加到现有草稿。重新发送失败的问题不清空当前草稿。
   - 语音输入：结果追加到当时的草稿，保留语音进行中键入的文字，只追加新增结果。
   - 第三方登录回调：完成后刷新界面，延后到页面构建完成后执行，避免启动时出错。
   - 已核实无需改动：复习作答、模型设置、云设置、学习设置的字段原本就同步到内存状态。弹窗挂在 `#app` 外，重绘不受影响。请求进行中导航和语言切换已锁定。
   - 验证：`tests/drafts.test.js` 2 项。隔离 fixture 内验证了以下情况，语音由页面内模拟的 SpeechRecognition 触发，不是真实麦克风：重发失败问题保留草稿；新建或切换对话保留草稿；追问追加；语音追加且保留键入内容；重绘后焦点与选区不变；卡片编辑草稿经重绘和语言切换保留，放弃、保存正常。
   - 限制：答案下方“查看来源”、复习讲解等只读折叠区在重绘后仍会收起。

6. **先复习昨天内容的队列策略**（`review-store.js` 的 `reviewQueue`）：
   - “昨天的内容”指今天之前最近一个学习日新建的卡片；隔几天再打开时，仍是上次学习那天的内容。
   - 顺序：当天答错或仍不理解的重练（约 10 分钟后）→ 上次学习日的卡片（重点优先，再按学习先后）→ 更早的到期卡（薄弱 → 重点 → 最早到期）。
   - 防止饿死旧卡：上次学习日的卡片最多占当日计划题量的一半（向上取整），并按今天已做的题数扣减，避免逐题重算后新卡占满。任一组不足时由另一组补位。
   - 自主加练保持同样顺序，不受配额限制。复习页说明文字已同步。
   - 验证：`tests/review.test.js` 新增 3 项，用逐题模拟整段复习：10 分钟计划先 3 道昨天的内容、再 3 道旧卡；单组补位；隔天打开；错题 10 分钟后优先；加练顺序。隔离 fixture 内用 5 分钟计划（3 题）实际作答，顺序为昨天 2 道 + 旧卡 1 道。
   - 限制：一半配额是可调的初始规则，没有学习效果数据校准。

7. **复习计划统计与跨时区**（`review-store.js`）：
   - 按真实用时计划：复习记录新增可选字段 `seconds`，从题目显示到选择反馈，上限 600 秒，离开页面的时间不会无限累计；旧记录没有该字段，照常读取。
     - 当日计划 = 计划分钟数 × 60 − 今天已用秒数（无记录的旧事件按 90 秒计），再除以每题估计用时。
     - 每题估计用时取最近 30 次有记录用时的中位数，限制在 30–300 秒；不足 3 次时按 1.5 分钟。
     - 复习页显示“今天已复习约 X 分钟，计划 Y 分钟”和当前估计。
   - 当天答错或仍不理解的题不受计划上限限制，10 分钟后仍会出现，符合“加入当天待复习”。
   - 跨时区与夏令时：按天的间隔不再比较存储的绝对时刻，而是“复习当天的本地日期 + 间隔天数”与“当前所在地的今天”比较。只有 10 分钟重练使用绝对时间。向西飞行后不会在同一本地日重复出题，夏令时 23/25 小时的那天也不会提前或推迟。存储格式不变，无需迁移。
   - 顺带修复：上次学习日的卡片组原先只按创建时间排序；长期缺席且积压卡都来自同一天时，同一批卡可能每天重复出现。现已加入到期时间排序。
   - 已核实是设计行为，保持不变：自主加练包含未到期和当天新建的卡；正常排程不含当天新卡，从次日开始。
   - 验证：`tests/schedule.test.js` 6 项，测试在运行时切换 TZ，已确认在 Windows 的 Node 上生效。覆盖新加坡 → 伦敦向西飞行、纽约夏令时开始与结束日、60 张积压卡分批（每天不超过计划、10 天内全部覆盖）、按真实用时的计划与超出计划后的重练、周日规则、用时上限与旧记录兼容。隔离 fixture 内实际作答后记录了用时，旧格式记录正常载入。
   - 限制：用时为页面可见时间的粗略估计，没有区分思考和离开。

**新增：本机 JSON 导入（2026-11-01）**

- 位置：设备页“数据备份”。只接受本 App“导出 JSON 备份”生成的文件，文件只在浏览器内读取，不上传，大小上限 2,000 万字符。
- 校验：用与云恢复相同的 `validateSnapshot`，任一部分不合格即整份拒绝，并说明是哪部分。
- 预览与确认：通过后显示文件名、导出时间和对话、消息、卡片、复习记录数量，须勾选确认才写入。
- 写入：替换而非合并，先把当前记录（连同账号归属）存为本机备份，最多 3 份；写入失败全部回滚；随后立即载入，无需刷新。
- 撤销：设备页和账号页都可“撤销上次替换”，交换且可再次撤销。
- 账号关联：导入的数据不关联云账号，之后上传须先确认“本机记录属于当前账号”。
- 验证：`tests/local-space.test.js` 新增 2 项。隔离 fixture 内以页面生成的导出格式文件验证：非导出文件被拒、超长问答被拒并指明部分、确认前不改动、未勾选被拒、导入后语言与问答即时切换且归属清空、撤销恢复原数据与原归属。未在浏览器中点击“导出”触发真实下载。
- 更新：已支持“合并到本机数据”，见第 8 项第 5 步。合并时保留本机设置和账号归属；替换时清除归属。

## 4. 后续路线

### A. 先稳定现有闭环

修复上述已知问题；完善复习历史可视化、错误判题纠正、卡片原文修订关联；保存未发送草稿；补必要的持久化、取消、冲突与恢复测试。保持轻量 UI。

### B. 真实服务联调

通过用户在 App 内填写的 Key 验证模型/搜索/提炼/判题；不要要求用户把 Key 发到聊天。云项目按 `cloud-setup.md` 配置后验证 OTP、PKCE、RLS、冲突、注销和加密密钥取回。外部项目与密钥目前没有，不应伪造。

### C. 多端与可靠后台能力

确定共享前端、后端与各原生壳路线；当前 Node 服务仅 loopback，手机不能直接访问电脑的 127.0.0.1。需要真实部署、鉴权、HTTPS/区域配置和请求限额，而非直接改监听 0.0.0.0 当成完成。

为 Android/iOS/Windows/macOS 建立工程、构建、更新、通知、系统安全存储与真机检查。PWA 可以作为阶段体验，但不能宣称已有原生安装包。后台推送需真实推送基础设施，不能用页面定时器假装可靠。

### D. 发布预留，暂不执行

中国/海外服务差异、日志脱敏、限额、数据迁移/导出/删除、隐私与通知同意、发布材料和签名配置。用户最终要上架，但当前明确暂缓发布，不能自动购买、注册或提交。

## 5. 外部缺项

未提供：模型 Key、Supabase 项目、邮件/短信服务凭据、Google/Apple OAuth 凭据、域名/部署账户、推送密钥、各平台签名证书与开发者账户。缺这些不阻止先完成本地实现、测试、适配和文档。
