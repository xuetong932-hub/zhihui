## 2. 验证范围

- 自动测试数量此前为 20 项；本次交接重新执行的实际结果见 `VALIDATION_REPORT.txt`，以报告为准。
- `npm run check` 对运行脚本做语法检查，不是完整浏览器集成测试。
- 测试使用受控 Response 和隔离 fixture，没有调用真实模型或真实 Supabase，也没有发送真实验证码。
- 历次浏览器检查使用 Chrome/Edge/应用内浏览器，约 390px 窄屏无横向溢出；不是 Android/iOS 真机测试。
- 帮助功能是可逆界面改动，未为其额外添加镜像实现的单测；已完成实际交互验证。

## 3. 建议马上处理的 P0/P1

以下是基于交接时静态代码审阅的明确风险/待核查项，不要误称已经修复：

1. **本地多账号隔离缺口**：`cloud-ui.js` 登录退出只处理云 session，浏览器本地学习数据仍是单份固定 key。没有按用户命名空间隔离；切换账户后可能把本机其他人的数据上传给当前账号。公开多人使用前必须解决，退出/切换需明确归属及迁移。
2. **云恢复后内存未即时重载**：下载替换 localStorage 后，`app.js` 和各 UI 仍持有旧对象，需刷新；刷新又清除 session 与模型 Key。已有“仅取回模型 Key”，但总体流程还不顺畅。设计安全重载/账户切换和回滚，不静默覆盖。
3. **取回 Key 的成功提示需要核实**：`cloud-ui.js` 的 `cloud-unlock-key` 解密后只查 model 是否存在；`acceptModelKey` 对格式不合法时静默不接受，调用处仍可能显示成功。统一严格校验与明确返回值。
4. **本地数据验证不完整**：`loadReviews` 未完整校验 correct/explanation 等字段；知识卡片、导入/云恢复数据也应统一 schema 与大小限制。未来公开接口不能信任浏览器存储或自行声明成年。
5. **状态竞争与弹层处理**：页面级锁、云回调、语音识别结束回调会触发全页重绘。审查导航、正在答题时切卡、弹窗关闭/语言切换时的草稿、请求取消与数据保存。不能丢失已输入内容。
6. **优先昨天知识尚非明确队列策略**：现在排序为薄弱 → 重点 → 到期时间；老积压可排在昨天的新内容前。与用户“第二天先依据昨天内容提问”对照实现兼顾策略，别饿死旧卡。
7. **复习计划统计与跨时区**：当前每次事件按约 1.5 分钟折算，上限针对全局事件而非真实耗时。主动加练会包含未到期卡；正常排程不包含当天新卡。补充跨时区/DST、错误后同日再练、周日与长期缺席测试。
8. **账号年龄与合并**：前端生日门槛可绕过，云 OTP 发送的是 adult_confirmed 自报元数据。服务端准入、已有账号登录限制、身份提供商绑定与重复账号合并仍未实现。

## 4. 后续路线

### A. 先稳定现有闭环

修复上述已知问题；完善复习历史可视化、错误判题纠正、卡片原文修订关联；保存未发送草稿；补必要的持久化、取消、冲突与恢复测试。保持轻量 UI。

### B. 真实服务联调

通过用户在 App 内填写的 Key 验证模型/搜索/提炼/判题；不要要求用户把 Key 发到聊天。云项目按 `cloud-setup.md` 配置后验证 OTP、PKCE、RLS、冲突、注销和加密密钥取回。外部项目与密钥目前没有，不应伪造。

### C. 多端与可靠后台能力

确定共享前端、后端与各原生壳路线；当前 Node 服务仅 loopback，手机不能直接访问电脑的 127.0.0.1。需要真实部署、鉴权、HTTPS/区域配置和请求限额，而非直接改监听 0.0.0.0 当成完成。

为 Android/iOS/Windows/macOS 建立工程、构建、更新、通知、系统安全存储与真机检查。PWA 可以作为阶段体验，但不能宣称已有原生安装包。后台推送需真实推送基础设施，不能用页面定时器假装可靠。

### D. 发布预留，暂不执行

中国/海外服务差异、日志脱敏、限额、数据迁移/导出/删除、隐私与通知同意、发布材料和签名配置。用户最终要上架，但当前明确暂缓发布，不能自动购买、注册或提交。

## 5. 外部缺项

未提供：模型 Key、Supabase 项目、邮件/短信服务凭据、Google/Apple OAuth 凭据、域名/部署账户、推送密钥、各平台签名证书与开发者账户。缺这些不阻止先完成本地实现、测试、适配和文档。
